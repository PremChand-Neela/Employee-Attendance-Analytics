# REVIEW.md: Code Review of Starter Application

This document reviews the defects discovered in the initial starter application (`app/main.py`), detailing where they occurred, the root cause, observable symptoms, and the applied architectural fixes.

---

## 1. Identified Defects & Resolutions

| # | Where (Function / Line) | Defect & Root Cause | How You'd Notice It (Test / Input / Symptom) | How It Was Fixed |
|---|---|---|---|---|
| **1** | `health` | Always returned `{"status": "ok"}` without testing database connectivity. | Stop or disconnect MongoDB and issue `GET /health`. It still returned HTTP 200 instead of 503. | Added `client.admin.command("ping")` inside a `try/except` block, returning HTTP 503 when the database is unreachable. |
| **2** | `create_employee` | Duplicate `emp_code` protection relied on check-then-insert (`find_one` followed by `insert_one`), creating a race condition. In addition, `created_at` used naive local time and serialized as an ISO string instead of epoch milliseconds. | Concurrently dispatch two identical `POST /employees` requests with the same `emp_code`. Both succeed with 201. Or inspect the response body: `created_at` was a string. | Added a unique index on `employees.emp_code`, catch `DuplicateKeyError` to return HTTP 409, and serialize `created_at` as UTC epoch milliseconds (`int64`). |
| **3** | `list_employees` | Offset calculation was `page * page_size` (skipping page 1), `total` ignored the `department` query filter, results were unsorted, and query bounds were unchecked. | Request `GET /employees?department=Engineering&page=1`. First page items were skipped, and `total` reflected the entire collection rather than the filtered count. | Computed `skip = (page - 1) * page_size`, filtered `total` with `count_documents(q)`, added sort by `emp_code` ascending, and enforced `page >= 1`, `1 <= page_size <= 100`. |
| **4** | `compute_late_minutes` / `punch_in` | Timestamps converted epoch milliseconds into server-local naive time causing incorrect dates across timezones; missing employee threw unhandled 500; invalid statuses were accepted; check-then-insert lost punch-in races. | Punch in near midnight IST on an overnight shift, send an unknown `emp_code`, supply status `ABSENT`, or send simultaneous punch-ins for the same day. | Normalized instants to UTC, derived attendance date in IST using shift boundary logic (R1), validated employee existence (404), enforced presence-only statuses, and enforced uniqueness via compound index `(emp_code, date)`. |
| **5** | `compute_work_hours` | Python's built-in `round()` uses round-half-to-even (banker's rounding), violating business rule R4. Additionally, punch instants retained sub-second milliseconds. | Punch durations with exact halves (e.g. 8.125 hours) rounded down to 8.12 instead of half-up to 8.13. Fractional seconds skewed elapsed duration. | Truncated punch instants to whole seconds prior to arithmetic and utilized `decimal.Decimal` with `ROUND_HALF_UP` for exact financial rounding. |
| **6** | `compute_overtime` | Assumed shift end was always on the same calendar day (breaking overnight shifts), lacked the mandatory 30-minute threshold (R3), and mixed timezone-naive with timezone-aware datetimes. | Punch out after an overnight shift (e.g. 22:00 to 06:00) or punch out 25 minutes after shift end. Overtime was miscalculated or credited under 30 minutes. | Calculated overnight shift end on the next calendar day (`attendance_date + 1 day`), enforced `elapsed >= 30` minutes minimum, and aligned all instants in UTC. |
| **7** | `list_attendance` | Loaded the entire collection into Python memory (`list(db.attendance_logs.find())`) and sorted in Python; leaked internal MongoDB `_id`; skipped validation for `date_from > date_to` and status enum. | In a dataset with 100,000 documents, requests timed out or exhausted server memory. Sending `date_from > date_to` did not return HTTP 422. Internal `_id` appeared in JSON. | Replaced in-memory sorting with MongoDB query filter, `count_documents`, index sort `[("date", -1), ("emp_code", 1)]`, `skip`/`limit`, and validated query parameters. Excluded `_id`. |
| **8** | Missing Core Endpoints | Punch-out, regularization with audit trail (`PATCH`), monthly employee analytics, department summary, late leaderboard, department trend, and explain were completely absent. | Calling any unimplemented route returned HTTP 404 or 405. | Implemented all endpoints adhering to `openapi.yaml`, leveraging atomic MongoDB operations and native aggregation pipelines. |
| **9** | PyMongo Database Aggregation | The initial trend implementation called `db.aggregate(...)` on a PyMongo `Database` object, which does not exist in PyMongo and raises `AttributeError`. | Calling `GET /analytics/departments/{department}/trend` crashed with `AttributeError: 'Database' object has no attribute 'aggregate'`. | Used `db.command("aggregate", 1, pipeline=..., cursor={})` to execute database-level pipelines cleanly through the driver. |
| **10** | Index Coverage on Analytics | Indexes were missing for `date` + `late_minutes` and department lookups, causing collection scans (`COLLSCAN`) during large-scale leaderboard and summary queries. | Running `explain` on `/analytics/leaderboard/late` against a 100k-record collection resulted in a full collection scan (`COLLSCAN`). | Created compound index `[("date", 1), ("late_minutes", 1), ("emp_code", 1)]` and compound employee indexes `(department, joined_on)` / `(joined_on, department)`. |

## 2. What Was Examined and Decided NOT to Be a Defect

1. **String Representations for Dates and Shift Times**:
   - `date` (`"YYYY-MM-DD"`) and `shift_start`/`shift_end` (`"HH:MM"`) are stored as strings. We verified against `DATA_MODEL.md` that calendar dates and times-of-day are deliberately plain strings to prevent accidental timezone offsets from mutating calendar boundaries.
2. **Exclusion of MongoDB `_id`**:
   - The API uses `emp_code` as the immutable human/business identifier and composite key `(emp_code, date)` for attendance records. The internal BSON `_id` is excluded from all request/response schemas by design.
3. **Strict Grace Period Inequality (`> 600` seconds)**:
   - Rule R2 explicitly states that punch-in is late only if strictly more than 10 minutes past shift start (09:40:00 is on time; 09:40:01 is 10 minutes late). The strict inequality in the starter was verified as mathematically correct and preserved.
4. **Returning 409 on Concurrent Regularization Conflict**:
   - Optimistic concurrency control verifies that the record's existing status, punch times, and history match the baseline state before applying changes. When a race condition occurs, returning HTTP 409 prevents lost updates without requiring heavy distributed locking.
